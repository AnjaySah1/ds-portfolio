# Reflection: Portfolio 2A, Binary Search Tree

For this part, I built a templated BST<T> class in BST.h with a private Node struct containing a value, left pointer, and right pointer, along with a root pointer. I started by implementing recursive insert and search, then added inorder, preorder, postorder, and level-order traversals. I also implemented the recursive size() and height() functions. Testing with an empty tree, duplicate values, integers, and strings helped me check that the basic operations worked correctly. Making commits as I finished each part helped me keep track of my progress.

The hardest part for me was implementing a `remove()` function. Removing a leaf node is straightforward because it can simply be deleted, and a node with one child can be replaced by that child. However, removing a node with two children requires more care because the BST ordering must be maintained. I used the in-order successor, which is the smallest value in the right subtree. It is the right choice because it is larger than everything in the left subtree and not larger than anything else in the right subtree, so the order is kept. I copied its value into the node being removed and then removed the successor from the right subtree. I used removeHelper and minNode to handle this. I tested removing a leaf, a node with one child, a node with two children, the root, and a value that was not in the tree.

For level-order traversal, I used a std::queue to visit nodes one level at a time. For a tree built from the values 50,30,70,20,40,60, and 80, the output was 50 30 70 20 40 60 80. This helped me understand how level-order traversal differs from inorder, preorder, and postorder. Instead of following the recursive traversal pattern, it uses a queue to keep track of which node to visit next.

The Rule of Three was another important part of this Portfolio because the BST manages dynamically allocated memory. Without a proper copy constructor, copying a tree would only copy the root pointer, causing both trees to try to free the same memory. I used copyHelper to create a separate copy of every node. My copy assignment operator also checks for self-assignment and creates the copy before deleting the old tree. To test this, I copied a tree, removed a value, added another value to the copy and printed both trees to make sure the original remained unchanged. I also implemented a destructor to free the allocated nodes.

If I continued working on a similar project, I would try adding balancing to the BST. When values are inserted in sorted order, the tree can become a long chain, making operations like search and insert take linear time. An AVL tree could help solve this problem by performing rotations after insertions or removals to keep the tree balanced. What helped me most was understanding how the in-order successor lets me remove a node with two children without breaking the BST ordering.
